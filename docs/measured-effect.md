# Что измерено и что остаётся проверить

Измерение 23.09.2026, расчётная версия `01b10ac`. Новое измерение не изменяет прогнозную модель и не подбирает её параметры по финальным месяцам. Исходные данные компании остаются на ноутбуке; опубликованы [агрегаты и все повторы](workflow-benchmark.json).

## Время полного автоматического прохода

В каждом повторе заново читаются шесть XLSX, рассчитывается прогноз, строится сетка сценариев, создаётся Excel со всеми рекомендациями в памяти. Это не утверждённый менеджером заказ. Тест читает файл обратно и проверяет число строк; эта последующая проверка не включена в таймер. Чтение исходных файлов включено. Streamlit-кэш не используется; файловый кэш ОС может быть прогрет.

| Поставщик | Товаров | Повтор 1, с | Повтор 2, с | Повтор 3, с | Медиана, с |
|---|---:|---:|---:|---:|---:|
| Systeme Electric | 724 | 11,657 | 11,469 | 11,069 | **11,469** |
| IEK | 3184 | 56,310 | 59,202 | 59,485 | **59,202** |

Один ноутбук, macOS arm64, Python 3.14.7, Pandas 3.0.6, NumPy 2.5.3. Время не включает браузер, загрузку по сети, физический пересчёт и действия менеджера. Это длительность автоматической обработки, **не сравнение с ручной работой и не обещание производительности на другом компьютере**. В JSON отдельно указаны импорт, прогноз, сценарии и экспорт.

```bash
python scripts/measure_workflow.py --root "/путь/к/папке-с-поставщиками" --repeats 3 --output workflow-benchmark.local.json
```

В папке нужны подпапки `Systeme electric` и `IEK`, по шесть XLSX. Дата расчёта 23.09.2026, поставка 21 день, пересмотр 14, страховой запас 7; общая ML-модель, рост из сводки выключен; сетка остатка/спроса ±20%, задержка 0/7 дней. Команда не публикует исходные строки.

## Какие решения меняются

| Наблюдение при проверенных допущениях | Systeme Electric | IEK |
|---|---:|---:|
| Уточнение остатка может переключить заказ да/нет | 47 | 350 |
| Изменение остатка может переключить срочность | 14 | 305 |
| Задержка +7 дней создаёт новую срочность при выбранном известном остатке | 1 из 497 | не оценено: нет текущих остатков |
| Можно сравнить заказы с фильтром и без него | 497 | 0 |
| Заказ меняется при включении фильтра | 10: 5 меньше, 5 больше | не оценено |

В первых двух строках меняется только остаток при фиксированных остальных факторах, внутри указанной сетки. Группы пересекаются, их нельзя складывать в число уникальных товаров. 397 товаров в первой строке — сумма 47 и 350 по двум разным каталогам. Это адресная очередь проверки, не подтверждённый дефицит 397 товаров.

Сравнение фильтра использует одинаковые входы и настройки, меняется только `remove_outliers`. Общая модель повторно обучается на изменённом спросе, поэтому некоторые рекомендации могут увеличиться. Сравнение не использует оценку будущего качества и не доказывает экономию; натуральные количества разных товаров не суммируются. Для IEK отсутствие сравнимых заказов означает неизвестный актуальный остаток, а не нулевой эффект.

## Как измерить бизнес-эффект

Следующий этап требует участия закупщика и согласования с владельцем кейса; он **не выполнен** в этой проверке.

1. Зафиксировать одинаковые входные файлы, актуальный остаток, справочники MOQ/кратности и сроки. Выбрать сопоставимые наборы SKU, единицы и поставщиков.
2. Провести ручную подготовку в текущем Excel-процессе и подготовку с Axioma. Чередовать порядок и использовать сопоставимые наборы, чтобы повторное знакомство с данными не выдать за пользу системы.
3. Для каждого задания записать начало/конец, активное время менеджера, время ожидания, число проверенных строк, исправлений и ошибок. Проверку результата делать по одинаковым правилам и отдельно от автора расчёта.
4. Сравнить медиану активного времени и долю исправлений на нескольких заданиях. Только после этого считать относительное изменение времени `(Excel − Axioma) / Excel`. Показать все задания, а не лучший пример.
5. Для финансовой оценки наблюдать новый период: фактические продажи, доступность, отмены, цены, стоимость хранения и дефицита. Согласовать контрольную группу/период и влияние сезонности. Меньший заказ без этих данных не считать сэкономленными деньгами.

До завершения пилота не публикуются проценты сокращения труда, денежная экономия или снижение фактического дефицита. Подготовленный протокол не выдаётся за состоявшееся внедрение.
