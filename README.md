# Axioma — объяснимые заказы поставщикам

Прототип команды Axioma для HackAlem AI, кейс Электрокомплект «Автоматический расчёт заказов поставщикам для пополнения склада».

Менеджер загружает Excel, получает рекомендации с объяснением, проверяет количество и выгружает утверждённые позиции. Отправки поставщикам нет.

## Установка и запуск

Python 3.11–3.14 (проверено на macOS, Python 3.14). Интернет нужен для установки зависимостей. Демо работает без API-ключей, аккаунтов, подписок и файлов компании.

macOS / Linux, в папке репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

Открыть http://localhost:8501. На macOS после установки можно дважды нажать `start.command`.

## Проверка основного сценария

1. Оставьте «Показать пример»: встроены 6 синтетических товаров, история 2024–2026, дата расчёта 23.09.2026.
2. Во вкладке «Почему столько» выберите DEMO-001: разовый заказ на 1500 единиц в августе. Переключите исключение всплесков, сравните прогноз.
3. Выберите DEMO-004: известный stockout 01–20.07.2026. Переключите компенсацию и сравните восстановленный спрос.
4. В «Данные и допущения» измените свободный остаток или множитель категории. Результат пересчитывается.
5. Скачайте рекомендации. В «Проверить и утвердить заказ» отметьте строки, измените количество, скачайте утверждённый Excel. Минимум и кратность проверяются.
6. Проверьте влияние сезонности, тренда, срока поставки и дополнительного прироста.

```bash
python -m pytest -q
```

Тестируются арифметика, путь и сроки, неизвестный остаток, MOQ/кратность, stockout, сезонность, категория, прирост, выбросы накладных и клиента за день, исключение неполного месяца и будущих данных, интерфейс.

## Импорт реальных данных

Режим «Файлы поставщика»: выбрать IEK или Systeme Electric, загрузить все шесть XLSX. Тип определяется по заголовкам, повреждённая кодировка имени файла не мешает. Ключ объединения — строковый код 1С. Артикул поставщика сохраняется отдельно.

| Источник | Использование |
|---|---|
| Детальные продажи | Дата, Номер, Документ, Код, Номенклатура, Ед., Склад, Количество; опционально client_id |
| Месячные продажи | Натуральный спрос по месяцам |
| Месячные остатки | Снимки; не точная длительность отсутствия |
| Путь IEK | Количества и даты поступления из заголовков |
| Путь Systeme Electric | Сводка, текущий свободный остаток, категории, поступление |
| MOQ | IEK — минимальная отгрузка; Systeme Electric — кратность |
| Сезонность | Готовая колонка СЕЗОННОСТЬ как профиль поставщика |

Продажи из отдельного месячного отчёта имеют приоритет перед сводкой. Месячные и детальные продажи не суммируются: детализация служит для поиска выбросов. Складская детализация пока агрегируется по поставщику, отдельный склад не выбирается.

Опциональная переменная `AXIOMA_DATA_DIR` — локальная папка с подпапками `IEK` и `Systeme electric`. При её установке появляется кнопка открытия предоставленных локальных файлов. По умолчанию папки не читаются. Это настройка только локального запуска.

### Дополнительные CSV

Актуальные остатки и правила можно редактировать на странице или загрузить:

```csv
sku,stock,category,pack,moq
DEMO-001,25,1,10,1
```

Обязательны sku и stock. pack — кратность в единицах учёта, moq — минимум. Коды хранить текстом. Периоды отсутствия:

```csv
sku,start,end
DEMO-004,2026-07-01,2026-07-20
```

Обе границы включены. Пересекающиеся периоды объединяются по дням.

## Методология расчёта

1. Используются завершённые месяцы до даты расчёта; неполный текущий месяц исключён. Отрицательные количества сохраняются как корректировки; отрицательный спрос не прогнозируется.
2. Строки накладной по товару и дню объединяются. При минимум 8 положительных наблюдениях порог выброса — `max(5 × median, Q3 + 3 × IQR, 1)`. Подозрительный объём заменяется медианой. При client_id дополнительно проверяется суммарная покупка клиента за день, включая несколько накладных. Это эвристика, а не обученный классификатор; менеджер может проверить исходный и исключённый объём.
3. Исключённый объём вычитается из месячного итога. Без детализации доступно консервативное сравнение с минимум двумя предыдущими одноимёнными месяцами.
4. Для известных stockout-дней продажи масштабируются на полный месяц по дням наличия. Для целого месяца отсутствия берётся медианный дневной спрос соседних месяцев. Отдельное явно включаемое приближение по нулевому месячному снимку заменяет заниженный спрос медианой, не заявляя точных дней отсутствия. Пустой остаток не считается нулевым.
5. Сезонность SKU оценивается по полным годам дневных продаж. При готовом профиле поставщика смесь: 80% SKU + 20% поставщик; при короткой истории — профиль поставщика. Коэффициенты ограничены и нормированы к среднему 1. Это допущение: денежная сезонность поставщика не равна натуральной сезонности каждого SKU.
6. База — средний очищенный и десезонализированный дневной спрос последних 6 месяцев. Тренд — отношение последних 3 месяцев к предыдущим 3, ограниченное −50…+100%. Дополнительный прирост задаёт пользователь. Будущий спрос учитывает календарную сезонность.
7. `Период = срок новой поставки + интервал пересмотра`. `Цель = спрос периода + дневной спрос × страховые дни × множитель категории`.
8. Вычитаются свободный остаток и ожидаемые поступления с известной датой внутри периода. Неизвестные/просроченные поступления требуют уточнения; поздние показываются отдельно. Дефицит до новой поставки проверяется по дням.
9. Положительный заказ доводится до MOQ и округляется вверх по кратности. При нулевой потребности MOQ не создаёт заказ. Неизвестный текущий остаток блокирует количество заказа.

21 день поставки, 14 дней пересмотра, 7 страховых дней — видимые стартовые допущения, не условия поставщиков. Множители категорий по умолчанию 1: смысл кодов категорий нужно согласовать и настроить.

## Архитектура

- `app.py`: Streamlit, настройки, ручное утверждение, Excel-экспорт.
- `src/data.py`: адаптеры Pandas/OpenPyXL, генерация синтетического демо.
- `src/engine.py`: детерминированный расчёт NumPy/Pandas, аномалии, объяснения.
- `tests/`: pytest, Streamlit AppTest.

Данные и кэш находятся в памяти процесса. Утверждение сохраняется только в текущей сессии и скачанном файле. Базы истории, многопользовательской авторизации и промышленной защиты сервера нет; прототип предназначен для локального запуска.

## Соответствие кейсу и ограничения

| Требование | Реализация и граница |
|---|---|
| Базовая потребность | Шесть видов файлов, текущий свободный остаток, путь, настраиваемые категории/прирост |
| Сезонность и рост | Профили SKU/поставщика, тренд, видимые переключатели |
| Упущенный спрос | CSV подтверждённых периодов; отдельно отмеченное приближение |
| Разовые продажи | По накладной; при client_id — по клиенту за день |
| Заказы по поставщикам | Контекст выбранного поставщика, объяснение каждой позиции, Excel |
| MOQ | Минимум и кратность; единицы требуют согласования |

В предоставленной детализации нет ID клиента: номер накладной его не заменяет. Точных ежедневных stockout-периодов нет. Для IEK отсутствует актуальный свободный остаток: месячный снимок не подменяет текущий, нужен ввод/CSV. В сводке Systeme Electric текущий остаток есть лишь для части каталога.

Кабель может закупаться бухтами и учитываться метрами: нужно задать кратность в единицах учёта, автоматического справочника конвертации нет. Пустое значение месячных продаж трактуется как ноль, пустой остаток — как неизвестный.

Нет измеренной точности на отложенной реальной выборке, экономической оптимизации, гарантированного уровня сервиса, цены и суммы заказа, прямой интеграции с 1С. Excel — обменный формат, совместимость с конкретным загрузчиком 1С не заявляется. Заказы одного клиента между разными днями отдельно не объединяются.
